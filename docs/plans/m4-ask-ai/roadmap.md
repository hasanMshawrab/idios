# m4 - Ask AI

Status: complete 2026-08-31. Both build steps shipped; the tuning loop ran
against a live cluster, changed no prompt text, and its two composition
fixes landed (see `prompts.md`, "Tuning notes").

Goal: an [Ask AI] button on the incident detail that hands the incident to
an AI agent two ways: a short prompt for a local agent that pulls its own
evidence over a new read-only idios MCP server, and a self-contained
snapshot prompt for an agent with no access to the machine. The milestone
is small and specific: the MCP server, the two generated prompts, the
button, and a manual tuning loop against a written rubric.

## Decisions (made, do not relitigate)

1. The MCP server is read-only. No acknowledge, no resolve, no delete;
   the human acts in the application.
2. The MCP server is a client of the daemon's HTTP API on the loopback
   interface, through the generated Go client, in the same binary as a
   subcommand (`idios mcp`, stdio transport). It never opens `idios.db`;
   the single-writer rule and the "only the daemon touches the database"
   boundary apply to it exactly as to the application.
3. No redaction in this milestone except environment values and secret
   material. Phase 2 audits whether any surface exposes them (the raw
   `pod.json` artifact is the suspect: inline `env:` values); whatever it
   finds is stripped by one shared sanitize package used by both the MCP
   artifact tool and the snapshot builder. Log content is served as
   captured.
4. No size budget on the snapshot. The application offers copy to
   clipboard and save to file, and tells the user the size before either.
5. Prompts are generated by the daemon, not assembled in Swift, so the
   prompt and the MCP tool vocabulary can never skew across versions.

## Steps

Two build steps that run in parallel as one agent each, then a manual
loop. The only seam between them is `internal/sanitize`: step A owns and
creates it, step B calls it; if B lands first it creates the package and
A adopts it.

### A. MCP server (one agent: Go)

`idios mcp` speaks MCP over stdio and translates tools into calls on
`127.0.0.1:7770` (or `-daemon`), using the committed generated client.
Evaluate the official Go SDK (`modelcontextprotocol/go-sdk`) first and
pin what is chosen. Tools, mirroring how an investigation actually runs:

- `list_incidents` - the existing filters: state, category, cluster,
  namespace, workload, pod uid, job uid (job uid is the sibling link).
- `get_incident` - detail plus timeline for one id.
- `get_pod` - pod detail: containers, conditions, the whole event
  stream, history.
- `read_log` - one artifact by id, with `tail_lines`, a byte `range`, or
  a `grep` pattern; never the whole file unless asked. This is the tool
  that keeps a 100 KB log from costing 100 KB of context.
- `read_pod_json` - the captured pod.json, sanitized.
- `get_workload`, `get_status` - orientation.

Includes the sanitize work: audit where environment values or secret
material can appear on these surfaces (the raw pod.json is the suspect:
inline env values; log content is out of scope by decision 3) and write
`internal/sanitize` - env values replaced by a marker, names kept - with
a fixture pod.json asserted whole after sanitizing. A daemon that is not
running answers every tool with one clear error naming the listen
address. Tests: a stdio harness driving the server against `idios mock`,
asserting tool output shapes whole.

Hands to the next phase: `sanitize.PodJSON(raw []byte) ([]byte, error)`
returns the captured object with every `env` value and the
`last-applied-configuration` annotation replaced by `sanitize.Redacted`;
it errors when the bytes are not a JSON object.

### B. Prompts and the button (one agent: Go then Swift)

`GET /v1/incidents/{id}/prompt?mode=mcp|snapshot` returns text/plain.
Mode `mcp` is the short prompt: incident identity and one-line summary,
the tool vocabulary, the investigation order, the answer rules. Mode
`snapshot` composes the full evidence: detail, timeline, containers and
conditions, the pod's whole event stream, log content per captured file
(whole is fine, decision 4; each section delimited, truncation marked),
sanitized pod.json (via `internal/sanitize`), related incidents by job
uid. Both prompts end with the same answer rules (see `prompts.md`); the
response carries the byte size.

Then the button: the incident detail toolbar gains [Ask AI] with "Copy
prompt for a local agent (MCP)", "Copy full snapshot" and "Save snapshot
as...". Copy puts the daemon's text on the clipboard, save writes where
the user chooses, both show the size first; a short explainer names what
the MCP option requires, with the config snippet
`{"command": "idios", "args": ["mcp"]}`.

### C. Prompt tuning loop (manual, the user drives)

The reference scenario and the answer rubric live in `prompts.md`. The
loop: reproduce the scenario with `make smoke`, click both buttons,
paste each prompt into a fresh local agent session, bring both answers
back, score them against the rubric, adjust the prompt text in step B,
repeat. Prompt text changes only when an answer misses a rubric line.
