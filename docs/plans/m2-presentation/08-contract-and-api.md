# Phase 8: contract, read models, API

**Goal:** the daemon answers every read endpoint of `presentation.md`
Section 4 and both streams of Section 5 over loopback HTTP, from a proto
contract compiled by sebuf, so the macOS application (Phase 9) has one
source of types and a running server to build against.

**Architecture:** `api/proto/idios/v1/*.proto` is the contract; `buf
generate` writes Go messages, the handler interface and the Go client to
`internal/apigen/idiosv1` and the OpenAPI document to
`api/openapi/`. `internal/query` holds one function per row set over a
`store.Querier`. `internal/api` implements the generated interface, maps
`query` structs to wire messages, serves artifact files, merges runtime
facts, and turns `notify` events into SSE. `internal/notify` is the
in-process broadcast the processor, closer, watcher and supervisor call
after a commit. `cmd/idios run` starts the listener as a component;
`idios status` reads `GET /v1/status` when the daemon is up.

**Tech stack:** Go 1.26 (toolchain go1.26.7), `modernc.org/sqlite`
v1.57.0, `k8s.io/*` v0.37.0, `github.com/SebastienMelki/sebuf` v0.23.2
(runtime `sebuf/http`), `buf.build/go/protovalidate` (pulled in by the
generated binding), `buf` 1.52, `protoc-gen-go`,
`protoc-gen-go-http`, `protoc-gen-go-client`, `protoc-gen-openapiv3`.

**Spec:** `presentation.md` Sections 2, 3, 4, 5, 6, 10, 11, 13;
`data-storage.md` Section 5 for every column named below.

**Global constraints:** every `.ai/*.md` rule; roadmap decisions 1
(Go 1.26 first), 2 (proto compiled by sebuf, generated files committed
and never edited), 3 (wire rules, Section 3.1), 4 (endpoint, handler,
client operation; never RPC), 8 (fixtures cross the boundary once). Plus
the m1 decisions in `CLAUDE.md`: reads through `store.Reader`, store SQL
in `internal/store` one file per area, `clock.Format` for every stored
timestamp, ASCII only, one commit per green task.

Facts the tasks depend on that are not in the design docs:

- sebuf applies `(sebuf.http.enum_value)` to JSON bodies only, never to
  query or path parameters (sebuf issue 219). Request filter fields are
  therefore `string` and the handler validates them, returning a
  `*sebufhttp.ValidationError` (400). Response fields stay typed enums.
- A handler error is a 500 unless a `WithErrorHandler` option maps it.
  `api` returns a sentinel `notFoundError` and the handler writes 404
  with `sebufhttp.Error{message}`.
- The generated server marshals with `protojson`; `int64` is a JSON
  string and unset `optional` fields are absent by default. No
  `WithMarshalOptions` is passed.
- Raw bytes cannot be a proto response. `GET /v1/artifacts/{id}/content`
  is a plain `http.HandlerFunc` on the same mux, not in the proto and not
  in the OpenAPI document; the Swift client fetches it with `URLSession`.
- sebuf's `stream: true` gives the handler a `SSESender` with `Send(msg)`
  and the client a stream with `Next(msg) bool`, `Err()`, `Close()`.
- Generated Go for `option go_package = "idios/internal/apigen/idiosv1;idiosv1"`
  lands in `internal/apigen/idiosv1/` when every plugin gets `module=idios`.

## Task 2: contract and generation

Files: `buf.yaml`, `buf.gen.yaml`, the seven proto files, `Makefile`
targets `generate` and `generate-check`, `cmd/idios/api_cmd.go`.

Wire rules, applied to every message:

- ids and byte counts `int64`; exit code, signal, restart count,
  occurrences, event count, all counts `int32`.
- Enums in `common.proto`, each value carrying
  `(sebuf.http.enum_value)` equal to the store constant:
  `Category`, `CloseReason`, `IncidentState` (`open`, `acknowledged`,
  `recovered`, `pod_deleted`, `job_finished`, `manual`, `dismissed`),
  `CaptureGap`, `DeletionSource`, `DeletionReason`, `ContainerKind`,
  `ContainerState`, `ArtifactKind`, `SubjectKind`, `TimelineKind`
  (`container_transition`, `condition`, `event`, `capture`, `rollout`,
  `lifecycle`, `cut`), `LifecycleStep` (`opened`, `closed`).
  Zero value `*_UNSPECIFIED` without `enum_value`.
- Raw Kubernetes values (reasons, phases, condition types, event reasons,
  messages, images) are `string`. Timestamps are `string`.
- Nullable columns are `optional`. No `nullable`, no `int64_encoding`.
- Every list response has exactly one `repeated` field plus
  `bool truncated`.
- Request messages: path variables are plain fields named as in the path;
  filters are `(sebuf.http.query)` fields. `repeated int64 cluster_ids`
  on every list. Filter values with a closed vocabulary (`state`,
  `category`, `live`) are `string`, validated by the handler. `limit`
  is `int32`, 0 meaning the configured default.
- `field_examples` on every scalar field of every response message, with
  values shaped like the smoke run (`checkout-api-7d9f8b6c4-x2kqp`,
  `2026-08-27T14:03:11.482913Z`, `crash`, `137`), so the mock is useful.

State derivation is one SQL expression, defined once as a constant and
reused by every incident query:

```sql
CASE WHEN dismissed_at IS NOT NULL THEN 'dismissed'
     WHEN closed_at IS NOT NULL THEN close_reason
     WHEN acknowledged_at IS NOT NULL THEN 'acknowledged'
     ELSE 'open' END
```

"Open" for `ByCategory` and `ByCluster` means state `open` or
`acknowledged`. `ExitCode` and `Signal` come from the subject
container's `last_terminated_exit_code` / `last_terminated_signal`;
`ContainerCount` is `COUNT(*) FROM containers WHERE pod_uid`. Order:
`last_seen_at DESC, id DESC`. An empty `ClusterIDs` means all clusters;
the `IN (...)` list is built from placeholders, never by formatting.

`internal/processor/processor_test.go` does (`crash-loop`, `oom`,

`replicaset/deploy.json` for rollout rows, `event-*` for events), then

dismissed incident with direct `UPDATE`s, and one `sweep_runs` row. The

Span: `[opened_at, COALESCE(closed_at, last_seen_at)]`. Events: attached
to the incident, or `involved_uid = pod_uid` with `last_ts` in the span.
Rollouts: `rollout_history` rows of the pod's `workload_name` in the
same cluster and namespace with `first_seen_at` in the span, one entry
per ReplicaSet (first container row). Lifecycle: `opened` at
`opened_at`; `closed` at `closed_at` when set. There is no reopen entry:
the row does not keep a reopen time, and the spec sentence is corrected
in this task (Section 4.2: "open, close" instead of "open, reopen,
close"). Cut: the newest `sweep_runs` row with `rows_removed > 0`,
`table_name` in (`container_state_history`, `pod_condition_history`,
`k8s_events`) and `cutoff` inside the span becomes one `cut` entry at
`K8sAt = cutoff`, `ObservedAt = ran_at`. Sort: `COALESCE(k8s_at,
observed_at)`, then `observed_at`, then kind order as listed in the
enum, then id, so the order is total.

Handlers `GetIncident` (404 through `notFoundError`, non-numeric id is
sebuf's 400) and `IncidentTimeline`; mapping functions
`incidentDetail`, `timelineEntry`.

## Task 11: notifier and the two streams

Section 5; Section 11 item 4.

`internal/notify/notify.go`:

```go
// Notifier broadcasts "row id changed" to every subscriber. It keeps no
// history: a client that connects late reloads the list first.
type Notifier struct{ ... }
type Kind int
const ( Incident Kind = iota; Cluster )
type Event struct{ Kind Kind; ID int64 }
func New() *Notifier
func (n *Notifier) Notify(k Kind, id int64)
// Subscribe returns a channel closed when ctx ends. A subscriber that
// falls 256 events behind is dropped (its channel closed): the API
// client reloads on reconnect, so dropping is safe and blocking the
// processor is not.
func (n *Notifier) Subscribe(ctx context.Context) <-chan Event
```

Producers, each after its transaction committed:

- `processor.Processor` gets `SetNotifier(n interface{ Notify(notify.Kind, int64) })`
  (nil means silent) and reports every incident id it opened, attached,
  reopened or closed, in `Pod`, `Event`, `PodDeleted`, `Job`,
  `JobDeleted`, and the cluster id in `ClusterConnected` and
  `ClusterError`. `store.CloseOpenIncidents` returns `[]int64` (SQLite
  `RETURNING id`) instead of a count so the ids are known; callers that
  used the count use `len`.
- `incident.Closer` gets the same setter; `store.CloseStableIncidents`
  returns `[]int64` likewise, and `TickResult.Closed` stays a count.
- `k8s.Config` gets `ReadyChanged func(bool)`; the watcher calls it when
  `ready` flips. The supervisor passes a closure that notifies the
  cluster, and notifies the cluster ids it started or stopped in
  `reload` (watched namespace set changes arrive as a restart).

`internal/api/streams.go`: `StreamIncidents(ctx, req, sender)`
subscribes, and for every `Incident` event loads the row with
`query.ListIncidents(IncidentFilter{ClusterIDs: req.ClusterIds, ID:
id})` (`IncidentFilter` gains `ID int64`, 0 meaning any) and sends it;
a row outside the requested clusters, or deleted meanwhile, is skipped.
Throttle: per incident id, at most one send per `cfg.APIStreamThrottle`;
a burst inside the window sends the latest row once when the window
ends, so the client always ends on the current row. `StreamClusters`
does the same with `query.ListClusters` filtered to the id and the
runtime merge. Both return when the client goes away (`ctx.Done()`) or
the notifier drops the subscriber (channel closed), which the client
sees as end of stream and reconnects.
